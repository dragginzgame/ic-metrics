# Rust 1.85 minimum-version qualification

The compatible pending 0.2.15 batch starts from released 0.2.14
`dee5ecdef3d811dcda930ddcaae48abf08acc951`, with the reviewed tooling integration
in [the adoption record](adoption-0215.md) already present. The package version
stays 0.2.14. The only compiler contract changes are workspace `rust-version`,
the Make `MSRV` default and the configured CI minimum compiler, all 1.85.0.
Edition 2024, resolver 3, development Rust 1.99, arithmetic sources, lock selection
and public APIs remain unchanged. No function, method or type is removed.

Rust 1.85.0 was not prepared on this host. The initial target-list probe attempted
to resolve an absent toolchain through the shared Rustup home and failed on its
read-only temporary directory. Explicit preparation then installed the minimal
1.85.0 toolchain and Wasm standard library in repository-owned
`target/toolchains/msrv-185/`. Compiler identity is
`rustc 1.85.0 (4d91de4e4 2025-02-17)`, host `x86_64-unknown-linux-gnu`.
Preparation uses Rustup's pinned-version download verification; it changes no
project dependency graph. Build outputs stay in `target/msrv-185/` and logs,
compiler details and original source/lock digests in `target/evidence/msrv-185/`.

Before changing the declaration, exploratory locked offline native and Wasm
`cargo +1.85.0 check -p ic-metrics --ignore-rust-version` commands pass. These
only establish compiler acceptance despite the old declared floor. After the
declaration change, actual `make msrv` passes without that bypass, invoking both
locked native and `wasm32-unknown-unknown` checks on 1.85.0.

Focused unit execution on 1.85.0 passes:

- `cargo +1.85.0 test -p ic-metrics --lib --locked constant_evaluation`: histogram
  construction/rejection/recording, summary recording and checked-mean constants.
- `cargo +1.85.0 test -p ic-metrics --lib --locked
  checked_mean_preserves_empty_zero_and_floor_division`.
- `cargo +1.85.0 test -p ic-metrics --lib --locked
  checked_mean_rejects_inconsistent_and_saturated_fields`.
- `cargo +1.85.0 test -p ic-metrics --lib --locked
  inclusive_bounds_assign_each_sample_to_one_bucket`.

All six selected unit cases pass. The three public doctests, including the
packaged application guide, pass with `cargo +1.85.0 test -p ic-metrics --doc
--locked`. Warning-denied Wasm documentation also passes. These commands select
the isolated Rustup home, disable auto-install and network resolution, and retain
the exact lockfile. Native/Wasm development Clippy passes with warnings denied
after `make fmt`; formatting, dependency pins, snapshot, workflow and documentation
checks pass. Original arithmetic/test source and lock digests verify unchanged.

This completes the focused lowering investigation in
[#35](https://github.com/dragginzgame/ic-metrics/issues/35). Local Linux compiler
execution is not native macOS or hosted qualification of the uncommitted batch.
The configured Linux MSRV job now explicitly installs 1.85.0; future committed
consumer CI remains separate from earlier released 1.88 evidence. No full local
CI/product-test gate, sibling edit, package version change, commit, push, release
or publication runs. This records compatibility, not IC cost or timing evidence.
